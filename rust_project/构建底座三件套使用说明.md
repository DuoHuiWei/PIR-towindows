# PIREXX 构建底座三件套使用说明

## 1. 文件说明

当前仓库新增了三件与 Windows GNU 构建相关的文件：

- `toolchain.toml`
  - 构建环境配置文件
  - 记录 Rust toolchain、cargo target、MinGW 路径、CMake 路径、`secp256k1` 构建目录等信息
- `rebuild_secp256k1.cmd`
  - 底层库重建脚本
  - 负责重建 `secp256k1` 静态库并覆盖到 `.libs\libsecp256k1.a`
- `build_gnu_nightly.cmd`
  - 主构建入口
  - 负责切换正确 Rust 工具链、检查环境、调用 `rebuild_secp256k1.cmd`、再执行 Rust 构建

另有一个辅助脚本：

- `load_toolchain_env.ps1`
  - 用于从 `toolchain.toml` 读取配置并传给 `.cmd` 脚本
  - 平时不需要单独运行

## 2. 最常用的构建方式

### 2.1 完整构建

在 `cmd` 中执行：

```cmd
cd /d 当前rust协议代码目录 
build_gnu_nightly.cmd
```

默认行为：

1. 设置 Rust override 到 GNU nightly
2. 确保 `x86_64-pc-windows-gnu` target 已安装
3. 检查并提示当前 `.libs` 与源码时间关系
4. 重建 `secp256k1`
5. 执行 `cargo clean`
6. 执行 `cargo build -j1 --target x86_64-pc-windows-gnu`

预期产物：

- `target\x86_64-pc-windows-gnu\debug\pirexx_uread.exe`
- `target\x86_64-pc-windows-gnu\debug\helper.exe`

### 2.2 只检查环境

```cmd
cd /d 当前rust协议代码目录
build_gnu_nightly.cmd --check-only
```

用途：

- 确认当前目录是否切到了正确 GNU nightly
- 确认 target 和 PATH 是否正确
- 不执行实际编译

### 2.3 跳过 secp256k1 重建，仅重编 Rust

```cmd
cd /d 当前rust协议代码目录
build_gnu_nightly.cmd --skip-secp256k1
```

适用场景：

- 已确认 `.libs\libsecp256k1.a` 是最新的
- 这次只改了 Rust 代码

## 3. 单独重建 secp256k1

在 `cmd` 中执行：

```cmd
cd /d 当前rust协议代码目录
rebuild_secp256k1.cmd
```

默认行为：

1. 使用 `toolchain.toml` 中的路径配置
2. 用干净的 `secp256k1\build-codex` 目录配置 CMake
3. 执行 `mingw32-make`
4. 将生成的 `libsecp256k1.a` 覆盖到 `.libs\libsecp256k1.a`

可选参数：

- `--no-configure`
  - 跳过 CMake configure，只在已存在的 `build-codex` 上执行 `mingw32-make`
- `--verbose`
  - 打印更完整的命令信息

示例：

```cmd
rebuild_secp256k1.cmd --no-configure
```

## 4. 迁移到新机器时怎么做

优先修改：

- `toolchain.toml`

通常只需要改两类字段：

- `mingw_bin`
- `cmake_bin`

如果 Rust toolchain 名称或 target 不变，一般不需要改其他项。

迁移后的推荐验证顺序：

```cmd
build_gnu_nightly.cmd --check-only
build_gnu_nightly.cmd
```

## 5. 使用边界

- 当前唯一正式支持链路：
  - `nightly-2023-09-24-x86_64-pc-windows-gnu`
  - MinGW
  - `cargo build -j1 --target x86_64-pc-windows-gnu`
- 不支持把 MSVC 当作正式构建链路
- `build_gnu_nightly.cmd` 是日常主入口
- `rebuild_secp256k1.cmd` 是底层维护入口，不是主要开发入口

## 6. 常见判断

### 情况 1：改了 `secp256k1/src/secp256k1.c`，日志没变化

优先执行：

```cmd
rebuild_secp256k1.cmd
build_gnu_nightly.cmd --skip-secp256k1
```

或直接：

```cmd
build_gnu_nightly.cmd
```

### 情况 2：出现 `packed_simd` / `E0512` / `MSVC` 相关报错

优先执行：

```cmd
build_gnu_nightly.cmd --check-only
```

先确认是不是掉回了错误工具链。

### 情况 3：怀疑 `.libs` 是旧库

执行：

```cmd
build_gnu_nightly.cmd
```

主入口会先重建 `secp256k1`，比手工判断更稳。
