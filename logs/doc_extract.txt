我现在要做的是一个 客户端 服务器端双端PIR软件的原型开发。
整体技术栈是 rust核心协议+ python fastapi 后端+ 本地WEB拉起的客户端前端（服务器先不用页面 ）
（前端：纯 HTML + CSS + JavaScript
没有用 Vue、React 这些框架，也没有用 jQuery，就是最基础的前端三件套。
它只负责两件事：
给你提供按钮、输入框，让你上传文件、输入查询内容；
把后端返回的结果显示出来，比如成功 / 失败提示、文件内容、下载按钮。）
整体规划：
即先在一个常驻的python主程序中拉起对应的服务，
前期不分两台电脑，全都在同一台本机做原型
客户端 FastAPI、服务端 FastAPI，暂时写在同一个主程序里
模拟： 客户端 API-浏览器    浏览器→ 服务端 API   服务端 API- 文件夹存储点  客户端 API- 服务端 API 这五个沟通。
Rust 客户端、Rust 服务端代码目前也也先混在一台机器调试
原型调通以后，后期再拆分部署到两台不同远程机器
同一个 Python 项目里，启动两个不同端口的 FastAPI 实例
模拟客户端服务：127.0.0.1:8000
模拟远端服务器服务：127.0.0.1:8001
现在开发原型阶段，把两个 API（客户端 API + 服务端 API）塞进同一个 Python 主程序里，一点问题都没有，非常适合前期写代码、联调、测试。

三条通路
通路 1：浏览器 ↔ 本机 Python
用来：网页上传文件、网页下载文件
协议：HTTP FastAPI
（就是你现在网页界面在用的）
通路 2：本机 Rust ↔ 远程 Rust
用来：加密私有协议、核心业务数据交互
协议：你原来的加密 TCP，完全不用改
通路 3：浏览器/本机文件 ↔ 远程 Python（跨电脑传文件）
用来：把浏览器上传的文件，从你本机自动传到远程服务器
协议：FastAPI HTTP 接口，专门多加一组文件传输接口即可
